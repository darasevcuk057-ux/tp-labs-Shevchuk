1. Ветка — это не копия файлов, а просто метка, которая показывает на нужный коммит. Файлы хранятся в одном месте, поэтому ветка делается за секунду и места почти не занимает. И Git знает, что две ветки вышли из одной точки, поэтому может сам их соединить. А копия папки — это просто ещё одна папка, Git не понимает, что она связана с проектом, и объединять придётся вручную.

2. Ничего не потеряется. Вся история лежит в папке .git, а обычные файлы проекта — это просто последняя версия, вытащенная наружу. Удалил файлы, но .git остался — пишешь git restore ., и всё возвращается. Если наоборот удалить .git, то история пропадёт навсегда.

3. Можно и сразу в main, но тогда никто не проверит код перед тем, как он попадёт в основную ветку. Pull Request нужен, чтобы другие посмотрели изменения, чтобы прогнались тесты, и чтобы осталось видно, зачем это делали. Так main всегда остаётся рабочим. Если проект свой и один — можно коммитить напрямую.
